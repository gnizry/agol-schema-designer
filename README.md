# מעצב סכמת AGOL

כלי גנרי לעיצוב מבנה נתונים רלציוני ל-ArcGIS Online / Pro, לשימוש בכל פרויקט סקר שטח (Survey123 / Field Maps).
כל פרויקט הוא **קובץ סכמה אחד** בתוך Git; הכלי עורך אותו, בודק אותו, ומייצר ממנו סקריפט ArcPy ומילון נתונים.

## הפרדה בין הכלי לסכמות

- **ריפו זה (ציבורי)** מכיל רק את הכלי ופרויקט `example` גנרי. אין בו נתוני ארגון.
- **סכמות אמיתיות** נשמרות בריפו **פרטי נפרד**, בתיקייה לכל ארגון: `<org>/<key>.schema.js` והתוצרים ב-`<org>/generated/<key>/`.
- הכלי מחובר אליהן דרך כפתור **פתח תיקיית פרויקטים** (Chrome / Edge): הוא קורא את הסכמות מהתיקייה המשוכפלת במחשב ושומר אליה ישירות. שום מידע לא עובר בשרת.

## מבנה הריפו

```
index.html                    הכלי
js/app.js                     ממשק (כולל פתיחה/שמירה של תיקיית פרויקטים)
js/generators.js              ולידציה + מחוללי ArcPy / מילון נתונים (גנרי)
projects/manifest.js          פרויקטים שמגיעים עם הכלי (example)
projects/example.schema.js    פרויקט לדוגמה
tools/generate.js             node tools/generate.js [key]  → generated/ (אופציונלי, ללא דפדפן)
```

## הפעלה

- **אונליין (GitHub Pages):** Settings ← Pages ← Deploy from a branch ← `main` / root. הכתובת: `https://<user>.github.io/agol-schema-designer/`.
- **מקומי:** לחיצה כפולה על `index.html`.

## זרימת עבודה

1. פותחים את הכלי ← **פתח תיקיית פרויקטים** ← בוחרים את תיקיית ריפו הסכמות במחשב (בפתיחה הבאה: **המשך**).
2. בוחרים פרויקט בתפריט, או **פרויקט חדש…** (סכמה ריקה, או עותק של הפרויקט הפעיל).
3. עורכים. לשונית **בדיקות** צריכה להיות נקייה משגיאות.
4. **שמור לתיקייה** — כותב `<org>/<key>.schema.js` ואת התוצרים (סקריפט ArcPy, מילון נתונים MD/CSV).
5. ב-GitHub Desktop: Commit ו-Push בריפו הסכמות. היסטוריית ה-Git היא היסטוריית הסכמה.
6. ב-ArcGIS Pro מריצים את `create_<key>_schema.py`, ואז Share As Web Layer.

בדפדפנים בלי תמיכה בגישה לתיקייה (Firefox, Safari) יש ייצוא/ייבוא ידני של קובץ הסכמה.

## תיעוד פתרון קיים (ייבוא מ-AGOL, `js/discover.js`)

לפתרונות שכבר רצים באונליין: הכפתור **ייבוא פתרון מ-AGOL…** בסרגל העליון (פרויקט חדש), או **+ הוסף פריטים מהאונליין** בדיאגרמת הפריטים של פרויקט פתוח. נקודת התחלה: קישור או מזהה של פריט (עדיף האפליקציה או הדשבורד שהמשתמשים פותחים), כתובת FeatureServer, שאילתת חיפוש (`tags:…`, `group:…`) או תיקייה בתוכן שלי. הכלי עוקב אחרי ההפניות בין הפריטים (תוכן הפריט ו-relatedItems: דשבורד → מפה → שכבה, טופס → שכבה, תצוגה → שכבת מקור) עד העומק שנבחר, ובונה:

- `diagrams.agolItems`: פריט לכל רכיב והקשרים ביניהם, מקובצים לפי סוג. `itemLinks` ו-`itemEdges` ממולאים, כך שהסטטוס והקשרים מסומנים כקיימים ומאומתים.
- `entities`, `domains`, `relationships`: מהשירותים המתארחים (לא מתצוגות). כל ישות שומרת `src` (הרכיב ומספר השכבה). הערכים נשמרים כפי שהם באונליין, גם כשהם חורגים מכללי הפרויקט, ולכן לשונית "בדיקות" מראה את הפערים.
- `meta.imports`: מתי ומאיפה יובא, לסריקה חוזרת.

אחרי הסריקה מוצגת רשימת בחירה (סינון, "+ עם הקשורים" שמצרף את המקורות והצרכנים הישירים של פריט), ורק הנבחרים נכנסים לפרויקט. ברשימה גדולה (מעל 25) מסומנות מראש רק נקודות ההתחלה. רכיב מיותר מוסר בטבלת הפריטים ("הסר רכיב"), יחד עם השכבות שיובאו ממנו. "הוסף לפרויקט הנוכחי" מוסיף רק פריטים שעוד לא מקושרים, בלי לגעת בישויות. בקשות שינוי ותקלות משויכות לרכיב (`changes[].comp`), ובטבלת הפריטים מוצג מספר הפתוחות לכל רכיב. לא נמצא אוטומטית: מה שאף פריט לא מפנה אליו (Notebook, Webhook, סקריפט חיצוני). התחברות בשם משתמש וסיסמה בלבד (לא SAML).

## מושגי הסכמה

- **ישות**: שכבת נקודות, קווים או פוליגונים, או טבלה. GlobalID / OBJECTID נוצרים אוטומטית; Editor Tracking מוסיף Creator, CreationDate, Editor, EditDate.
- **קשר**: 1:N לפי `GlobalID` של האב ו-`ParentGlobalID` (GUID) בבן — המבנה ש-Survey123 משתמש בו עבור Repeat. COMPOSITE (מחיקת אב מוחקת בנים) או SIMPLE (ההיסטוריה נשמרת).
- **דומיין**: רשימת ערכים עם קוד, תווית, הורה ומפתח חיצוני (אופציונליים). "מפתח חיצוני" הוא קוד טכני לממשקים עם מערכות אחרות; הוא מועתק לשדה מחושב ולא משמש כקוד הדומיין.
- **כללי פרויקט** (`meta.rules`): `minTextLength` (למשל 255 — שדה טקסט שנוצר קצר קשה להרחבה בשכבה מתארחת) ו-`domainCodeEqualsLabel` (קוד = תווית, בלי קודים מספריים). הבדיקות מתריעות על חריגה.
- **דומיין (המשך)**: ה"הורה" מאפשר סינון מדורג (משפחה ← תת-דגם) ב-Survey123 (`choice_filter`).
- **שדה**: שם טכני, כינוי, סוג, אורך, דומיין, אופן קלט, תנאי תצוגה בטופס, סימון "פתוח" והערה.
- **החלטות פתוחות**: רשימה לכל פרויקט של נושאים שהאפיון משאיר פתוחים; שדות המסומנים "פתוח" מופיעים בה אוטומטית.

## תרשימים

בתפריט "תרשימים" שלוש תצוגות. כולן נגזרות מקובץ הסכמה, ולכן עובדות לכל ארגון:

- **ERD** (תרשים ישויות וקשרים): נבנה אוטומטית מהישויות והקשרים. אפשר לבחור כמה שדות להציג.
- **רכיבי הפתרון** (תרשים רכיבים): אנשים, אפליקציות, שירותי נתונים, עיבוד וצרכנים, והחצים ביניהם.
- **תהליכים**: זרימת משתמש וזרימת נתונים בתבנית נתיבים (swimlane). כל שורה היא גורם: אדם, אפליקציה או מערכת.

רכיבי הפתרון והתהליכים נקראים מהבלוק האופציונלי `diagrams` בקובץ הסכימה (`components` ו-`flows`). דוגמה מלאה בפרויקט signage. ללא הבלוק מוצגים ה-ERD ורכיב נתונים בסיסי. בכל תצוגה יש "העתק Mermaid", להדבקה במסמך Markdown בריפו (GitHub מציג אותו כתרשים), ו"הדפס / PDF".

## מה עדיין לא כלול

- מחולל XLSForm ל-Survey123 Connect (אותם דומיינים → choices, `parent` → choice_filter, תנאי תצוגה → relevant).
- Notebook להסבה משכבה שטוחה למבנה הרלציוני.
- Contingent Values ב-Field Maps.

## פרסום לשותפים (קישור קבוע)

כפתור **🌐 פרסם לשותפים (צפייה בכלי)** כותב לתיקיית האתר (בחירה חד-פעמית של תיקיית הריפו הזה) את `share/<key>/schema.js` ואת תמונות הדגמים. אחרי Commit ו-Push (והמתנה של 1-2 דקות) שני קישורים קבועים מציגים תמיד את הקוד והסכמה העדכניים:

- `https://gnizry.github.io/agol-schema-designer/?view=<key>`: כל הכלי במצב צפייה בלבד (סכימה, תרשימים, החלטות, סימולטור, ייצוא מסמך אפיון). זה הקישור שהכפתור מעתיק.
- `https://gnizry.github.io/agol-schema-designer/?sim=<key>`: הסימולטור בלבד, עם כפתור **💬 הערות** שאוסף משוב ומוריד אותו כקובץ טקסט.
- קישור קצר לפרויקט שילוט: `https://gnizry.github.io/agol-schema-designer/signage/` (תיקיית `signage/index.html` מפנה אל `?view=signage`). לפרויקט נוסף אפשר ליצור תיקייה כזו באותו אופן.

שינוי בסכמה או בתמונות מגיע לשותפים רק אחרי פרסום חוזר. הכפתור **📤 קובץ HTML בודד** מייצר גרסה עצמאית לשימוש בלי אינטרנט.

שים לב: הקבצים ב-`share/` ציבוריים, כי הריפו ציבורי. מתאים רק לסכמות לא רגישות.

## מסמך אפיון (Word / PDF)

בתפריט **📤 ייצוא ושיתוף** יש **מסמך אפיון (Word)** ו**(PDF)**, שנבנים מהסכמה הפעילה: סקירה, תרשים ישויות וקשרים, טבלת שדות לכל ישות, דומיינים, החלטות ושדות פתוחים, ונספח רכיבים ותהליכים אם הוגדרו. Word נוצר בדפדפן בעזרת הספרייה `js/vendor/docx.iife.js` (MIT); PDF נוצר מחלון ההדפסה של הדפדפן ("שמירה כ-PDF").

## סימולטור כללי (`js/simgen.js`)
סכמה עם `sim: { engine: 'generic', ... }` מקבלת סימולטור מונחה סכמה במקום סימולטור השילוט: שכבה ראשית (נקודה / קו / פוליגון) וטבלה קשורה אחת.
- **Field Maps**: שרטוט לפי תבנית (ערכי שדה הסטטוס), טופס עם קבוצות, שדות מותנים (`rel`), חובה (`required` / `reqIf`) ושדות מחושבים, פופאפ עם רשומות קשורות, וקישור העומק של כל כפתור.
- **סקריפט לילי**: איחוד רשומות "המשך" לרשומת "חדש" עם אותו מזהה (Multi-Part, ה-GlobalID של הראשי נשמר והבנים עוברים אליו) ומילוי שדות `script`.
- **טפסים**: התנהגות כל שדה בטופס. **נתונים**: הטבלאות אחרי הפעולות.

שדות התצורה מתועדים בראש `js/simgen.js`. דוגמה מלאה: `kkl/fire_scars.schema.js` בריפו הסכמות.
